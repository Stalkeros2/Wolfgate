# Intimacy

Interactive arousal, pleasure and lubrication between two adjacent bodies, offered through the same right-click menu
as every other verb.

Acts are prototypes (`Resources/Prototypes/_WF/Intimacy/acts.yml`), directional: the giver is the player choosing the
verb, the receiver is the body they clicked. A platonic set (wave, handshake, hug, high five, pat, beacon) needs no
consent, no anatomy and no session, so a body with no anatomy or no toggles still gets a usable list. Each act carries its own `Range`: the wave has none and reaches across the room, a handshake keeps to arm's length. Intimate acts are
only added for a pair where both have Adult content on and the receiver allows the body; the rest show as disabled with
the reason, which is how the menu teaches the rules.

The one new UI is the interaction window, opened by a single `Interactions…` verb: the server judges every act with `WFIntimacyRules` and sends the refusals with the list, so a row cannot drift from what the click will do. Everything else runs off `GetVerbsEvent<Verb>`, `DoAfter` and popups that reach only the two
participants. Consent is the existing `consentToggle` chain in `consent.yml` (receive, give, and one group per kind of
act), so the consent window lists it with no code. `WFAutoArousal` additionally caps the Anatomy panel's arousal slider
to the body's current value: once arousal builds on its own, the panel can lower it but not raise it.

A motion is a pulse: `WFIntimacyMath` turns the act, arousal, lubrication and afterglow into pleasure, arousal and
lubrication gains, and `ApplyPulse` is the only place that writes them. Manual use is a `DoAfter` of the act's interval
with `BreakOnMove`, re-checked every tick; the automatic cadence ("let it repeat") emits the same pulses on the server,
so spam-clicking and autothrust share one code path and one set of caps. The cadence is `WFIntimacyMath.Interval(act, speed)`, so slow and fast are the same path at different multipliers; intensity rides along in the session and starts scaling the gains in the next phase. A session opens on the first pulse and closes
on the stop verb, the idle timer, consent loss, death, or either body leaving range.

Clothing does not have to come off: `GenitalsComponent.Displaced` marks a region whose clothing has been moved aside
(the `Move clothing aside` self-verb), which `GenitalCoverageSystem.IsRegionOpen` counts as open while the garment stays
worn and drawn. Acts with `receiverRegion: None` (grind, kiss) work through clothing and build arousal slowly.

Tuning lives on `IntimacySettingsPrototype` (`WFIntimacyDefault`). Orgasm and session events (`WFIntimacyOrgasmEvent`,
`WFIntimacyStartedEvent`, `WFIntimacyStoppedEvent`) are the hooks for mess, mood, pregnancy or anything else added
later. Acts are logged under `LogType.WFIntimacy`.

`wf.anatomy_enabled false` fails every anatomy gate, which leaves only the platonic acts; `wf.intimacy_debug true` logs one line per right-click saying how many acts were offered or which gate left the menu empty (not a mob, no reach, no consent). With it on, a body nobody is playing also counts as present and consenting and is given the user's anatomy, so one client can test the whole chain; turn it off to get the real refusals back.

Entry points: `WFIntimacySystem` (the `Server` folder), `.Verbs.cs` (the one verb), `.Menu.cs` (the window list and its requests), `ClientIntimacySystem`/`WFInteractionWindow` on the client, `WFIntimacyRules` (the gate chain and its context, shared with the client), `.Validity.cs` (fills that context from the world), `.Rules.cs` (the smaller tests they are built from),
`.Pulse.cs` (one motion, orgasm), `.Session.cs` (open/close, clothing control), `.Drift.cs` (the clock).
